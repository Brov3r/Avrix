## 🛠️ Workshop-моды и Java-плагины

Avrix поддерживает два способа доставки:

1. **Ручной загрузчик** — скачать `Avrix-Loader-<version>.jar` и запускать через `java -jar`.
2. **Workshop-загрузчик** — подписаться на Workshop-мод Avrix и запускать обычный лаунчер игры с профилем
   `-pzexeconfig`.

Workshop-модель предназначена для пользователей Steam. Загрузчик, его профили запуска и моды с плагинами
обновляются через Steam. Ручной режим остаётся для выделенных серверов, не-Steam установок и разработки.

---

### 📦 Workshop-мод загрузчика

Workshop-мод Avrix содержит:

```text
mods/Avrix/
├── 42/
│   ├── media/...
│   └── mod.info
└── libs/
    ├── Avrix-Loader.jar
    ├── Avrix-windows.json
    └── Avrix-linux.json
```

`Avrix-Loader.jar` — тот же shaded-загрузчик, что используется в `java -jar`. JSON-файлы — это профили запуска для
нативного лаунчера Project Zomboid. Это не игровые ресурсы, поэтому они лежат рядом с JAR загрузчика.

После подписки добавьте профиль для вашей платформы в **Steam → Project Zomboid → Свойства → Параметры запуска**.

**Windows (Normal Launch):**

```text
-pzexeconfig ..\..\workshop\content\108600\3833849848\mods\Avrix\libs\Avrix-windows.json
```

**Linux:**

```text
-pzexeconfig ../../../workshop/content/108600/3833849848/mods/Avrix/libs/Avrix-linux.json
```

ID Workshop-мода Avrix — `3833849848`
([Steam Workshop](https://steamcommunity.com/sharedfiles/filedetails/?id=3833849848)).

`-pzexeconfig` — аргумент лаунчера. Если вы добавляете JVM-аргументы, указывайте их до разделителя `--`, который
использует Project Zomboid.

> [!IMPORTANT]
> Workshop-профиль работает через **обычный нативный лаунчер**. Он не работает с Alternate Launch
> (`ProjectZomboid64.bat` в Windows или `start-server.sh` в Linux). Для них используйте ручной `java -jar`.
>
> macOS пока не проверен. На macOS используется `JavaAppLauncher` внутри `Project Zomboid.app`; он может не
> поддерживать `-pzexeconfig`.

### 🧩 Структура мода с плагином

Java-плагин распространяется как обычный мод Project Zomboid. Положите Avrix-плагин в version-каталог мода и
объявите его в `mod.info`.

```text
MyJavaPluginMod/
├── 42/
│   ├── mod.info
│   └── media/java/MyPlugin.jar
└── common/                  # опционально
```

JAR — это обычный Avrix-плагин, внутри которого есть `metadata.yml`:

```text
MyPlugin.jar
├── metadata.yml
├── com/example/myplugin/MyPlugin.class
└── com/example/myplugin/MyMixin.class
```

Плагин может использовать те же `entrypoint`, `mixins`, зависимости, окружение и ограничения версий, что и плагин
из папки `plugins/`.

---

### 📝 `mod.info` и `jarPlugins`

Объявите один или несколько плагинов через ключ `jarPlugins`:

```ini
name=My Java Plugin
id=MyJavaPluginMod
require=\Avrix
author=YourName
versionMin=42.21.0
jarPlugins=media/java/MyPlugin.jar, media/java/MyPlugin-extra.jar
```

`require=\Avrix` объявляет Workshop-мод Avrix зависимостью Project Zomboid. Сам по себе он не запускает Java —
загрузчику всё ещё нужен launch-профиль `-pzexeconfig`, — но заставляет меню Mods учитывать зависимость и позволяет
загрузиться Lua-статусу/предупреждению Avrix. Моды с плагинами должны его указывать.

Правила:

- Ключ нечувствителен к регистру.
- Несколько путей разделяются запятой или точкой с запятой.
- Несколько строк `jarPlugins=` суммируются.
- Пути указываются относительно каталога с `mod.info`.
- Если `mod.info` лежит в `common`, а JAR — в version-каталоге (`42`, `42.21`, ...), Avrix также проверит этот
  version-каталог.
- Version-специфичный `mod.info` с `jarPlugins` перекрывает объявления JAR в `common`. `common` остаётся fallback,
  если выбранная версия не объявляет `jarPlugins`.
- Avrix выбирает самый высокий version-каталог, который не выше версии запущенной игры. Если все каталоги новее,
  используется ближайший более новый. Если версия игры неизвестна, используется самый новый каталог.
- Абсолютные пути, drive/UNC-пути, пути от корня и **любой** сегмент `..` отклоняются. Каждый путь `jarPlugins`
  должен оставаться внутри папки мода.
- Симлинки и junction’ы, ведущие за пределы папки мода, отклоняются.
- Каждый JAR должен существовать и быть корректным Avrix-плагином. JAR без Avrix-метаданных попадёт в ошибки
  загрузки.
- Мод должен быть **включён** в Project Zomboid. Java из отключённых/неактивных модов не загружается.
- После включения или отключения мода с `jarPlugins` перезапустите игру. Список активных модов читается при старте
  JVM, поэтому изменения текущей сессии применяются со следующего запуска.
- При `--strict` отсутствующий или некорректный `jarPlugins` прерывает запуск. Без `--strict` ошибка логируется и
  пропускается.

---

### ✅ Только активные моды

Avrix загружает `jarPlugins` только из модов, которые действительно включены игрой или сервером.

**Клиент** — `%USERPROFILE%\Zomboid\mods\default.txt`, блок `mods`:

```text
mods
{
    mod = MyJavaPluginMod,
}
```

**Выделенный сервер** — `%USERPROFILE%\Zomboid\Server\<servername>.ini`:

```ini
Mods=MyJavaPluginMod;OtherMod
```

Имя сервера берётся из `-servername`. Если аргумента нет, Avrix использует `servertest`.

Если список активных модов не найден, Avrix не загружает ни один `jarPlugins`. Ручная папка `plugins/` при этом
работает независимо и всё равно сканируется.

---

### 🔌 Совместимость с `plugins/`

Классическая папка полностью поддерживается:

```text
plugins/
├── MyPlugin.jar
└── disabled.txt
```

Оба источника объединяются, дедуплицируются по canonical path и сортируются по имени файла. `plugins/disabled.txt`
может отключить плагин по `id` или по имени архива независимо от того, откуда он пришёл — из `plugins/` или из мода.

Если одинаковый plugin ID есть в `plugins/` и в активном моде, **побеждает архив из мода**, а архив из `plugins/`
игнорируется с предупреждением. Дубликаты внутри одного источника (два архива в `plugins/` или два архива в модах)
по-прежнему являются ошибкой разрешения порядка загрузки.

### 🖥️ Выделенный сервер

Для выделенного сервера лучше использовать ручной `java -jar` или серверный скрипт запуска:

```bash
java -jar ./Avrix-Loader-<version>.jar -nosteam
```

Если на сервере используются Workshop-моды:

1. Включите моды в `Server/<servername>.ini` (`Mods=...`).
2. Запускайте сервер с соответствующим аргументом `-servername`.
3. Убедитесь, что Workshop-контент для app `108600` доступен в Steam-библиотеке сервера.

Avrix читает активные моды сервера из INI, поэтому плагины из неактивных серверных модов не запускаются.

---

### 🔐 Подтверждение плагинов

Архивы из доверенной папки `plugins/` загружаются без подтверждения. Архивы, найденные через `jarPlugins` в активных
Workshop- или локальных модах, проходят проверку по политике approval.

Политика задаётся JVM-свойством:

```text
-Davrix.plugin.policy=prompt
-Davrix.plugin.policy=deny-new
-Davrix.plugin.policy=allow-all
```

По умолчанию:

- клиент — `prompt`;
- выделенный сервер — `deny-new`;
- `prompt` на выделенном сервере заменяется на `deny-new`, потому что Lua-UI там нет.

Поведение:

| Политика | Поведение |
|---|---|
| `prompt` | Неизвестные/изменённые JAR не загружаются. В главном меню появляется **одно** батч-окно Lua. |
| `deny-new` | Неизвестные/изменённые JAR молча пропускаются. UI нет. |
| `allow-all` | Все JAR из активных модов загружаются без подтверждения. Только для разработки. |

Файлы approval хранятся в папке игры:

```text
<Project Zomboid>/avrix/plugin-approvals.txt
<Project Zomboid>/avrix/plugin-pending.txt
```

Lua-песочница Project Zomboid имеет доступ только к файлам внутри кэша игры, поэтому Avrix пишет туда зеркало и
читает оттуда файл решений:

```text
<кэш Zomboid>/Lua/avrix/plugin-pending.txt
<кэш Zomboid>/Lua/avrix/plugin-decisions.txt
```

`<кэш Zomboid>` по умолчанию равен `~/Zomboid` и следует аргументу запуска `-cachedir=`, если он указан.

Основное хранилище одобренных и список pending остаются в папке игры. Lua только читает зеркало pending и пишет
файл решений; Avrix применяет его при следующем запуске.

Сценарий:

1. Avrix сканирует активные `jarPlugins`, считает SHA-256 и не загружает неизвестные/изменённые архивы.
2. Lua-мод показывает **одно** батч-окно со списком pending-плагинов.
3. Нажмите на плагин, чтобы переключать **пропуск → разрешить → запретить → пропуск**. `Allow all` и `Deny all`
   заполняют все строки, `Apply` сохраняет строки с выбранным решением, `Later` закрывает окно без сохранения.
4. Строки, оставленные на **пропуске**, не сохраняются и остаются в pending — окно спросит о них при следующем
   запуске.
5. Одобренные хэши загружаются без повторного вопроса. Изменённый JAR требует повторного подтверждения.

Явный **запрет** запоминается для конкретного хэша JAR. Чтобы спросить снова, удалите
`<Project Zomboid>/avrix/plugin-approvals.txt` (или соответствующую строку) и перезапустите игру.

`plugins/` остаётся доверенной папкой и в этом процессе не участвует. Моды с `jarPlugins` должны указывать
`require=\Avrix`, чтобы Workshop-мод и его Lua-UI approval были включены.

### ⚠️ Безопасность

Java-плагины имеют неограниченный доступ к системе. Avrix не является песочницей. Устанавливайте Java-плагины только
из источников, которым доверяете, и по возможности проверяйте исходный код.

Считайте любой активный мод с `jarPlugins` исполняемым кодом.

Lua-окно подтверждения — это шаг согласия и наглядности, а не граница безопасности. Любой включённый Lua-мод может
прочитать зеркало pending и записать файл решений, потому что все моды используют одну Lua-песочницу. Окно также не
защищает от мода, который поставляет собственный Java-плагин: вредоносный Lua-мод может изменить hand-off во время
работы игры. Проверяйте моды до включения и используйте `plugins/` только для полностью доверенного кода.

Не запускайте Avrix и ZombieBuddy одновременно на одном запуске игры. Оба фреймворка трансформируют классы, и их
совмещение может дать трудно диагностируемые конфликты.

---

### 🔍 Диагностика

- **Игра запускается без Avrix** — проверьте, что строка `-pzexeconfig` указывает на
  `libs/Avrix-windows.json` или `libs/Avrix-linux.json`, и что используется Normal Launch.
- **Плагин не загружается** — проверьте, что его мод включён в меню Mods (клиент) или в `Mods=` (сервер), что
  `jarPlugins` указывает на существующий JAR и что внутри JAR есть `metadata.yml`.
- **Мод отключён, но его Java всё равно работает** — уберите его из `default.txt` / `Mods=` или добавьте ID плагина
  или имя JAR в `plugins/disabled.txt`.
- **В игре появилось предупреждение, что Avrix не активен** — Workshop-мод включён, но профиль `-pzexeconfig`
  отсутствует или указан неверно.
