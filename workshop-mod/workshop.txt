description=[h2] ℹ️ About [/h2]
description=Avrix is a modern Java mod loader and mixin framework for Project Zomboid. It runs Java plugins from mods without repacking the game: it swaps the game classloader, applies ASM mixins, reads [i]metadata.yml[/i], and invokes plugin entrypoints. Requires [b]Java 25[/b], which is bundled with Project Zomboid Build 42.
description=
description=[hr][/hr]
description=
description=[h2] ❓ FAQ [/h2]
description=
description=[b]Q: How do I load Java plugins?[/b]
description=A: Put plugin JARs into the plugins folder, or distribute them through a Workshop mod using the [i]jarPlugins[/i] key in mod.info. Avrix loads jarPlugins only from active mods.
description=
description=[b]Q: What is the plugins folder?[/b]
description=A: It is the [i]plugins[/i] directory in the game directory. JARs placed there are treated as manually installed and trusted, so they load without the approval window. Use it for local or private plugins; Workshop plugins still go through approval.
description=
description=[b]Q: How does JAR approval work?[/b]
description=A: On launch Avrix opens one window listing all detected plugin JARs. Check the plugins you trust and press Apply. Unchecked plugins are denied and not loaded; approved ones load immediately. Enable "Remember for future launches" to keep your choices. Plugins that change after approval are asked again.
description=
description=[b]Q: What is the order of steps to load a Java plugin?[/b]
description=A: Enable the mod in the Mods menu, restart Project Zomboid, approve its JAR in the approval window, then press Apply. Approved plugins load in that same launch; no second restart is needed.
description=
description=[b]Q: Where are my approval decisions stored?[/b]
description=A: In [i].avrix/plugin-approvals.txt[/i] inside the game or server directory. Delete a line to ask again, or delete the file to reset all approvals.
description=
description=[b]Q: How do I approve plugins on a dedicated server?[/b]
description=A: Avrix prompts in the interactive console; if no console is attached but a GUI is available, it opens the Swing window. For non-interactive setups use [i]-Davrix.approval.frontend=console[/i] with piped input, or pre-approve through [i].avrix/plugin-approvals.txt[/i].
description=
description=[b]Q: Does Avrix work in multiplayer?[/b]
description=A: Yes. Avrix supports both the graphical client and the dedicated server, so it works in multiplayer. Install and configure it on the server, and on clients too if the plugin has a client-side part. CO-OP hosting from the client is client-side only; see the next question.
description=
description=[b]Q: Does Avrix work in CO-OP (hosting a server from the client)?[/b]
description=A: Only on the client side. CO-OP starts a separate server process directly as [i]zombie.network.GameServer[/i]; Avrix is not started in that process, so server-side plugins do not load there and the server never asks for approval. The approval window shown when the client starts applies to client-side plugins only, and its decisions are not transferred to the CO-OP server. For server-side plugins, run a dedicated server started through Avrix.
description=
description=[b]Q: Does Avrix work with ZombieBuddy?[/b]
description=A: Not recommended. Do not run Avrix and ZombieBuddy on the same game launch — both frameworks transform game classes, and combining them can cause hard-to-diagnose conflicts.
description=
description=[b]Q: Why use Avrix if ZombieBuddy already exists?[/b]
description=A: Avrix is a full plugin loader with Workshop distribution, plugin metadata, dependency resolution, load order, lifecycle/services and Sponge-style mixins. ZombieBuddy is a ByteBuddy patch framework; its patches need porting to Avrix. Pick one — do not run both at once.
description=
description=[b]Q: How do I disable a plugin without deleting it?[/b]
description=A: Create [i]plugins/disabled.txt[/i] and list one plugin ID or JAR name per line. Lines starting with # are ignored.
description=
description=[b]Q: Can I install Avrix without Steam?[/b]
description=A: Yes. Download [i]Avrix-Loader-<version>.jar[/i] from Releases, put it in the game root and run [b]java -jar Avrix-Loader-<version>.jar[/b]. Works for non-Steam installs and dedicated servers; add [b]-nosteam[/b] when needed.
description=
description=[b]Q: Do I need to install a JDK?[/b]
description=A: Not for the Workshop version: Build 42 bundles Java 25. A separate JDK 25+ is only needed for the manual [i]java -jar[/i] launch or plugin development.
description=
description=[b]Q: Does Avrix work on macOS?[/b]
description=A: Not verified yet. There is no native macOS launch profile; use the manual [i]java -jar[/i] model from the game-files directory inside the .app bundle.
description=
description=[b]Q: Can Avrix break my saves?[/b]
description=A: Avrix itself does not touch saves. Plugins and mixins can change game behavior, so back up saves before adding new plugins.
description=
description=[b]Q: How do I uninstall Avrix?[/b]
description=A: Remove the [i]-pzexeconfig[/i] launch option and unsubscribe from (or disable) the Workshop item. For a manual install, delete the loader JAR and the [i]plugins[/i] folder. The game then runs vanilla again.
description=
description=[b]Q: Is Avrix compatible with ByteBuddy?[/b]
description=A: Not recommended. ByteBuddy-based patchers and Avrix mixins both rewrite game classes at load time, so running them together can cause hard-to-diagnose conflicts. Use one approach at a time.
description=
description=[b]Q: Why aren't my plugins loading?[/b]
description=A: Make sure the mod is enabled in the Mods menu, the JAR is in [i]plugins/[/i] or listed in [i]jarPlugins[/i], it was approved in the approval window, and it is not listed in [i]disabled.txt[/i]. Check the game logs for the exact reason.
description=
description=[b]Q: Is Avrix open source?[/b]
description=A: Yes. Avrix is licensed under the MIT License.
